
# AWS Monitoring and Amazon CloudWatch

# 1. What is Monitoring?

Monitoring is the process of observing, collecting, and analysing information about the performance, health, and availability of IT resources.

In AWS, monitoring helps us understand whether our infrastructure and applications are working correctly.

### Why do we need monitoring?

- Monitor EC2 instance health.
- Track CPU and memory utilisation.
- Monitor network traffic.
- Identify application errors.
- Detect performance issues.
- Monitor database performance.
- Receive alerts when problems occur.

### What can we monitor in AWS?

| Resource | What to Monitor |
|---|---|
| EC2 | CPU utilisation, network traffic, disk metrics |
| RDS | CPU utilisation, database connections, storage |
| Lambda | Invocations, errors, execution duration |
| S3 | Storage metrics, requests |
| Application | Response time, errors |
| Load Balancer | Request count, latency, unhealthy targets |

---

# 2. What is Amazon CloudWatch?

Amazon CloudWatch is an AWS monitoring and observability service that collects and monitors metrics, logs, and events from AWS resources and applications.

### Main purposes

- Monitor AWS infrastructure.
- Collect application logs.
- Track resource performance.
- Create monitoring alarms.
- Visualise metrics through dashboards.
- Identify operational problems.
- Trigger automated responses.

**Remember:** CloudWatch helps you understand what is happening inside your AWS infrastructure.

---

# 3. Core Components of CloudWatch

## 3.1 CloudWatch Metrics

### What are Metrics?

Metrics are numerical measurements collected over time to monitor the performance and health of resources.

### Examples

| Metric | Meaning |
|---|---|
| CPUUtilization | Percentage of CPU being used |
| NetworkIn | Incoming network traffic |
| NetworkOut | Outgoing network traffic |
| DiskReadOps | Number of disk read operations |
| RequestCount | Number of requests |
| DatabaseConnections | Number of database connections |

### Example

Suppose an EC2 instance has the following CPU utilisation:

| Time | CPU Utilisation |
|---|---|
| 10:00 | 20% |
| 10:05 | 35% |
| 10:10 | 70% |
| 10:15 | 95% |

CloudWatch collects these measurements and allows you to analyse them.

### Important Exam Points

- Metrics are numerical data.
- Metrics are collected over time.
- CloudWatch stores metrics for monitoring.
- You can create alarms based on metrics.
- EC2 Basic Monitoring generally provides metrics at 5-minute intervals.
- EC2 Detailed Monitoring provides metrics at 1-minute intervals and may incur additional charges.

---

## 3.2 CloudWatch Logs

### What are Logs?

Logs are records of events generated by applications, operating systems, and services.

Example:

```text
2026-11-13 10:00:00 INFO User logged in
2026-11-13 10:01:00 ERROR Database connection failed
2026-11-13 10:02:00 WARNING High memory usage
```

CloudWatch Logs allows you to collect, store, search, and analyse log data.

### Important Concepts

| Concept | Meaning |
|---|---|
| Log Group | Collection of log streams |
| Log Stream | Sequence of log events from a source |
| Log Event | Individual log entry |
| Retention | How long logs are stored |

### When to Use CloudWatch Logs?

- Collect application logs.
- Monitor API errors.
- Identify database connection failures.
- Monitor operating system logs.
- Investigate application problems.
- Search and analyse log data.

**Important Exam Point:**

CloudWatch Logs is used for application and system log collection, storage, and analysis.

---

## 3.3 CloudWatch Alarms

### What is an Alarm?

A CloudWatch Alarm monitors a metric and changes its state when a defined condition is met.

### Example

You want to receive an alert whenever EC2 CPU utilisation exceeds 80%.

Alarm configuration:

```text
Metric: CPUUtilization
Threshold: Greater than 80%
Period: 5 minutes
Action: Send SNS notification
```

If CPU utilisation exceeds the configured threshold for the required evaluation periods, the alarm can enter the ALARM state.

### Three Alarm States

| State | Meaning |
|---|---|
| OK | Metric is within the configured threshold |
| ALARM | Metric has breached the configured threshold |
| INSUFFICIENT_DATA | Not enough data is available to evaluate the alarm |

### What Can CloudWatch Alarms Do?

- Send email notifications through SNS.
- Trigger Auto Scaling actions.
- Perform supported EC2 actions.
- Trigger other configured responses.

**Important:** An alarm detects a condition. Its configured action determines what happens next.

---

## 3.4 CloudWatch Dashboards

### What is a Dashboard?

A CloudWatch Dashboard provides a visual representation of metrics and monitoring information.

### What can you display?

- EC2 CPU utilisation.
- Network traffic.
- RDS database connections.
- Lambda errors.
- Application request counts.

### When to Use It?

When you want to monitor multiple AWS resources from a central location.

---

## 3.5 CloudWatch Events and Amazon EventBridge

### What is Amazon EventBridge?

Amazon EventBridge is a serverless event bus service that allows applications and AWS services to communicate through events.

### Examples

- An EC2 instance changes state.
- An AWS service generates an event.
- A scheduled event occurs.
- An application publishes a custom event.

**Important Exam Point:**

Amazon EventBridge is the successor to CloudWatch Events. For modern AWS architectures, learn EventBridge as the primary event-driven service.

# 4. CloudWatch Agent

### What is CloudWatch Agent?

The CloudWatch Agent is software installed on EC2 instances or on-premises servers to collect additional system-level metrics and logs.

By default, EC2 monitoring provides certain infrastructure metrics.

However, you may need additional information.

### Additional Information Collected

- Memory utilisation.
- Disk space utilisation.
- Swap utilisation.
- Application logs.
- Operating system logs.

### Standard EC2 Monitoring vs CloudWatch Agent

| Standard EC2 Monitoring | CloudWatch Agent |
|---|---|
| Provides standard EC2 metrics | Collects additional system metrics |
| CPU utilisation | Memory utilisation |
| Network traffic | Disk space utilisation |
| Basic disk I/O metrics | Application and operating system logs |

**Important Exam Point:**

If a question asks how to monitor EC2 memory utilisation, think of the CloudWatch Agent.

# 5. CloudWatch vs CloudTrail

This is an important AWS certification topic.

Although both services provide visibility into AWS environments, they serve different purposes.

## Amazon CloudWatch

Monitors resource performance and application behaviour.

Examples:
- CPU utilisation.
- Memory utilisation.
- Application logs.
- Network traffic.
- Monitoring alarms.

## AWS CloudTrail

Records AWS account activity and API calls.

Examples:
- Who terminated an EC2 instance?
- Who created an S3 bucket?
- Who modified an IAM policy?
- When was an API call made?

### Comparison

| CloudWatch | CloudTrail |
|---|---|
| Performance monitoring | API activity monitoring |
| Metrics and logs | API event history |
| Resource health | Account activity |
| Operational monitoring | Auditing and governance |

### Example

Suppose someone terminates an EC2 instance.

**CloudTrail answers:**
- Who terminated the instance?
- When was it terminated?
- Which API call was made?

**CloudWatch answers:**
- What was the CPU utilisation?
- What happened to application performance?
- Were there any monitoring alarms?

**Remember:**
- CloudWatch = How is my infrastructure performing?
- CloudTrail = Who performed an action in my AWS account?

# 6. CloudWatch vs AWS Config

Another important distinction for AWS certification.

| CloudWatch | AWS Config |
|---|---|
| Monitors performance and operational health | Tracks resource configurations |
| CPU utilisation | Security group configuration |
| Application logs | Configuration changes |
| Performance alarms | Configuration compliance |
| Operational monitoring | Configuration auditing |

**Example:**

If you want to know whether an EC2 instance's CPU utilisation is high, use CloudWatch.

If you want to know whether an S3 bucket's configuration complies with your organisation's rules, use AWS Config.

# 8. Quick Revision Notes

Memorise these associations:

- CloudWatch = Monitoring and observability.
- CloudWatch Metrics = Numerical measurements.
- CloudWatch Logs = Application and system logs.
- CloudWatch Alarms = Alerts based on metric conditions.
- CloudWatch Dashboards = Visual monitoring.
- CloudWatch Agent = Additional system metrics and logs.
- CloudTrail = AWS API activity and auditing.
- AWS Config = Resource configuration tracking and compliance.
- EventBridge = Event-driven application integration.
- SNS = Notifications and message delivery.

---

# 9. Important Exam Tips

1. Do not confuse CloudWatch with CloudTrail.
2. Remember that CloudWatch Metrics contain numerical measurements.
3. Remember that CloudWatch Logs stores log events.
4. Remember that CloudWatch Alarms monitor metric thresholds.
5. Remember that EC2 memory utilisation requires the CloudWatch Agent.
6. Remember that CloudTrail records API activity.
7. Remember that AWS Config tracks resource configurations.
8. Remember that SNS can deliver CloudWatch alarm notifications.
9. Remember that EventBridge handles event-driven workflows.

**Exam Strategy:** Focus on identifying the correct AWS service from the requirements described in a scenario.
